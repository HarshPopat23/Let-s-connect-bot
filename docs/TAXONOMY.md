# Situation taxonomy

The 50 categories are grouped by the part of the open-source journey where the situation is most likely to appear. Categories can still overlap because real contribution work crosses technical and social boundaries.

## Discover and orient

1. Onboarding and orientation
2. Project discovery
3. Project health and contributor fit
4. Repository navigation and architecture
5. Local development setup

## Work with Git and contribution provenance

6. Git foundations
7. Forks, remotes, and synchronization
8. Branches, commits, and history
9. Rebase, conflicts, and recovery
10. Commit signing and contribution provenance

## Work with issues

11. Issue discovery
12. Writing and reproducing issues
13. Issue assignment and takeover
14. Issue triage, labels, and duplicates
15. Design discussions and proposals
16. Stalled issues and missing responses

## Work with pull requests

17. Pull request preparation
18. Pull request descriptions and evidence
19. Pull request review and feedback
20. Stalled pull requests and missing review
21. Pull request CI failures
22. Pull request conflicts and obsolescence
23. Closed, rejected, and superseded pull requests

## Improve product quality and inclusion

24. Testing and quality assurance
25. Documentation contributions
26. Accessibility, design, and user experience
27. Localization and translation

## Participate in community

28. Community communication, channels, and meetings
29. Code of conduct and community conflict
30. Collaboration, pairing, and handoffs
31. Responsible AI-assisted contribution

## Protect projects and users

32. Security reports and private disclosure
33. Secrets, privacy, and sensitive data
34. Dependencies and software supply chain
35. Licenses, CLA, DCO, and trademarks

## Navigate programs and ecosystems

36. Google Summer of Code journey
37. LFX Mentorship journey
38. Outreachy and other mentorship journeys
39. CNCF, Kubernetes, and Kubeflow workflows

## Grow responsibility and sustain projects

40. Reviewer, triager, and maintainer growth
41. Governance and decision-making
42. Releases, backports, and deprecations
43. Non-code contributions
44. Career, portfolio, and reputation
45. Time management, burnout, and boundaries

## Handle advanced engineering and project lifecycle

46. API compatibility and breaking changes
47. Performance, reliability, and observability
48. Data, AI, and machine-learning projects
49. Cloud-native and infrastructure contributions
50. Project inactivity, migration, and forks
