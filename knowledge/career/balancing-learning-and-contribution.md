# Choose a sustainable weekly commitment

Open source is long-term collaboration. Reserve a realistic number of hours after coursework, health and essential responsibilities. Consistent focused sessions are more useful than occasional all-night contribution bursts.

# Connect learning to a real project

Learn fundamentals required by your chosen issue, then apply them immediately. Avoid completing large generic roadmaps before touching a repository. At the same time, do not use a production project as a substitute for basic language, testing and Git knowledge.

# Limit parallel work

Maintain one primary project and at most one backup while learning. Track the next concrete action for each. Too many claimed issues create shallow context and unreliable follow-through.

# Plan around review latency

Review is asynchronous. Keep independent learning or tasks available while waiting. Do not create artificial deadlines for maintainers because of exams or program applications.

# Measure progress well

Track concepts learned, bugs reproduced, tests written, review feedback applied, documentation improved and people helped. These measures encourage real skill development better than daily commit or pull request counts.
