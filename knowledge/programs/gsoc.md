# What GSoC is

Google Summer of Code is a global program that brings new contributors into open-source organizations through mentored projects. It is not a conventional employment internship. Eligibility, dates, project sizes, organizations and rules can change, so the current official program website is authoritative.

# Prepare before applications

Learn ordinary open-source contribution first. Explore organizations whose mission genuinely interests you. Read their ideas pages, contributor guide, communication channels, previous projects and current priorities. Run the project and make relevant contributions when the organization welcomes pre-application work.

Do not ask only which organization has low competition. A credible application requires project understanding, technical fit, communication and enough time to complete the proposed work.

# Communicate with the organization

Introduce yourself briefly in the specified public channel. Ask specific questions after reading existing material. Attend meetings and listen to current problems. Respect the organization's rules about contacting mentors and discussing proposals.

Contributions can demonstrate familiarity, but there is no guaranteed number of merged pull requests. One meaningful change with good review interaction can be stronger evidence than many superficial changes.

# Write an original proposal

Explain the problem, users, current behavior, goals, non-goals, technical design, milestones, deliverables, tests, risks, communication plan and other commitments. Reference your relevant investigation and contributions. Use a realistic schedule with buffer for review and unexpected complexity.

Do not copy past proposals or submit unverified AI-generated text. Every technical statement and milestone must be yours to defend. Follow the organization's proposal format even if a generic template looks better.

# Understand selection and rejection

Participating organizations select proposals based on their priorities, mentor capacity and allocated slots. Google does not choose each contributor proposal for the organization. Prior contribution can improve evidence but never guarantees selection.

If rejected, request feedback only when the organization offers it. Continue when the project remains meaningful, or use the experience to choose a better fit. Do not accuse individuals without evidence or harass selected contributors.

# AI use

Follow both GSoC and organization-specific AI policies. Validate and understand generated work. AI is most useful for learning, exploration, debugging assistance, boilerplate and candidate tests. The contributor remains fully responsible.
