# Before open source, software usually cost money

For much of computing's early history, useful software was not free to use or read. Operating systems, compilers and development tools were commercial products, often bundled with expensive hardware or sold under strict licenses that forbade viewing the source code at all. A student or hobbyist who wanted to understand how a compiler actually worked usually could not, because the code itself was the vendor's protected property.

This mattered because it meant improvement was slow and centralized. If a company's compiler had a bug, users waited for that company to fix it. If a student wanted to learn from real production code, there was often nothing legal to read. Software knowledge stayed locked inside a small number of organizations.

# The free software movement begins

In 1983, Richard Stallman announced the GNU Project: an effort to build a completely free Unix-like operating system that anyone could use, study, modify and share. In 1985 he founded the Free Software Foundation to support it. The GNU General Public License, first released in 1989, made this a durable idea rather than a one-time gift: it legally required that anyone who distributed a modified version of GPL-licensed code had to share their changes under the same terms. "Free" here meant freedom, not price, though most of this software also cost nothing.

In 1991, a Finnish student named Linus Torvalds released the first version of a kernel he called Linux, intending it to complete the GNU system's missing piece. The combination, usually called GNU/Linux, is what still powers most of the world's servers, nearly all public cloud infrastructure and the Android phone in most pockets today.

# "Open source" becomes a movement with a name

By the late 1990s, a related but distinct framing emerged. In 1998, Netscape released the source code of its web browser, which eventually became the Mozilla project and, later, Firefox. That same year, a group including Bruce Perens and Eric Raymond coined the term "open source" and founded the Open Source Initiative to define what the term should mean in practice, publishing the Open Source Definition as a checklist any license had to meet. The pitch to businesses was pragmatic: shared, inspectable code produces more reliable and more widely adopted software, not just more ideologically pure software.

# Foundations exist because volunteer projects need stewards

As open-source projects grew large enough to matter to entire industries, a problem appeared: a critical project should not depend entirely on one person's laptop, one company's goodwill, or one maintainer's availability. Nonprofit foundations were created to hold trademarks and infrastructure, provide neutral governance across competing companies, and make sure a project could outlive any single contributor or employer. The Apache Software Foundation (1999), the Linux Foundation (2000), the Mozilla Foundation (2003), the Python Software Foundation and the Cloud Native Computing Foundation (2015, home to Kubernetes and many CNCF projects referenced elsewhere in this knowledge base) all exist for this reason. When you contribute to a CNCF or Apache project today, you are contributing to something explicitly designed to survive any one company or person leaving.

# A concrete example: VLC did not start as a company product

VLC, one of the most widely used media players in the world, began in 1996 as a student project at a French engineering school, École Centrale Paris, originally built to stream video across the campus network. It was released under the GNU General Public License and developed further by the VideoLAN organization, a nonprofit. Nobody planned for it to become the media player many people worldwide now use daily. It grew because volunteers kept fixing bugs, adding format support and answering user reports, the same kind of work a first-time contributor does today.

# Why this history matters if you are just starting

Every large project you will contribute to, Linux, VLC, Kubernetes, Python, Firefox, started as unglamorous, incomplete work by people who were once exactly where you are now: reading someone else's code for the first time, unsure if their contribution mattered. The tools, licenses and foundations described above exist specifically so that a newcomer's small pull request can become a permanent, credited part of software used by millions. You are not adding a favor to somebody's side project. You are participating in a decades-old, still-active movement that was built, deliberately, to let exactly this happen.
