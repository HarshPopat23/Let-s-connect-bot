# Show impact, not a pull request count

Describe the project, user problem, your specific contribution, technical decision, collaboration and result. Link the issue and merged pull request. State status accurately when work is open or unmerged.

A strong entry explains why the change mattered and what evidence validated it. For example: added a regression test and fixed pagination state loss in a Kubernetes controller, addressing an issue reported by users and passing repository integration tests.

# Separate roles accurately

Contributor, member, reviewer, approver and maintainer are not interchangeable. Use the title documented by the project. Do not call a mentorship an internship if the program explicitly distinguishes them.

# Build a credible GitHub profile

Pin a small number of meaningful repositories or contributions. Write clear project READMEs. Keep contact links current. Public review discussions, tests and documentation can demonstrate professional collaboration better than a contribution graph alone.

# Discuss unmerged work honestly

An unmerged pull request can show investigation and review experience, but state that it is under review or closed. Explain what you learned and avoid presenting proposed code as released impact.

# Respect confidentiality

Do not publish private mentor conversations, applicant rankings, proprietary code or security details to strengthen a resume. Obtain permission before quoting or naming another person as an endorsement.
