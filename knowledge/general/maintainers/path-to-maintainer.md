# Maintainer is a trust role

A maintainer is responsible for the project's long-term health, not merely someone with merged code. Responsibilities can include review, release management, triage, roadmap decisions, security response, community care and governance.

# Build sustained trust

Contribute consistently in one project area. Understand users and architecture, write tests and documentation, respond well to review and follow through after merge. Help diagnose issues and review work without pretending to have authority you do not hold.

Welcome newcomers, improve contributor documentation and reduce repeated maintenance work. Reliability, judgment and communication matter alongside technical ability.

# Learn the contributor ladder

Read the project's governance and membership documents. Roles such as contributor, member, reviewer, approver and maintainer mean different things across projects. Some require a period of activity, documented contributions, nominations or sponsors.

Do not ask for a role only because you reached an informal pull request count. Ask for feedback on responsibilities you should demonstrate. Let existing maintainers confirm readiness through the documented process.

# Use authority carefully

Review consistently, disclose conflicts of interest, separate personal preference from project requirements and explain decisions. Do not merge your own controversial changes without required review. Protect security and private conduct reports.

# Avoid burnout

Set response expectations, document repeated answers, share ownership and take breaks. Being constantly available is not a requirement for good maintainership. Sustainable processes are better than dependence on one person.
