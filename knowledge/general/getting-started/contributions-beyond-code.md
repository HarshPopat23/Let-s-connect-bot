# Documentation and education

Improve installation instructions by testing them on a clean environment. Add missing examples, clarify concepts, correct outdated behavior, write tutorials, improve API references or translate documentation. Documentation changes should be technically verified and follow the project's style guide.

# Testing and issue quality

Reproduce reported bugs across supported versions, reduce a reproduction to the smallest case, identify regressions, add missing test coverage and test release candidates. A precise reproduction can save maintainers more time than a speculative patch.

Triage duplicate or incomplete issues only when the project permits community triage. Ask for missing versions, logs and reproduction steps respectfully. Do not close or label issues unless you have the appropriate role.

# Design, accessibility and user experience

Contribute interface research, accessibility audits, user flows, design systems, icons and usability testing. Discuss design work before producing large assets because projects may have branding or accessibility requirements.

# Community and operations

Welcome newcomers, answer questions using documented sources, take meeting notes, organize events, improve contributor onboarding, maintain project boards and help with releases. Avoid presenting yourself as an official project representative unless authorized.

# Localization, writing and advocacy

Translate interfaces and documentation, review translations, write accurate project articles, create demos and submit conference talks. Respect project trademarks and clearly distinguish personal opinions from official statements.

# Security and dependency work

Improve dependency updates, threat models, secure defaults, vulnerability reporting documentation and automated checks. Report suspected vulnerabilities privately through the project's security policy rather than a public issue.

# Review as contribution

Anyone with sufficient context can test a pull request and provide non-binding feedback. State what you tested and avoid approval language if the project reserves approval for reviewers or maintainers. Good review is specific, kind and supported by evidence.
