# Repository and fork

A repository stores project files and version history. A fork is a repository copy under another account that remains connected to the original. Contributors commonly push changes to their fork and propose them upstream.

# Clone and remote

A clone is a local working copy. A remote is a named repository location. `origin` usually points to your fork; `upstream` commonly points to the original project.

# Branch and commit

A branch is a movable line of development. A commit records a specific set of changes with identity and history. Projects may require a particular commit message or signed-off commit.

# Issue and discussion

An issue tracks a bug, feature, task or question according to project policy. A discussion is often used for open-ended questions or proposals before they become actionable work.

# Pull request

A pull request proposes merging changes from one branch into another. It includes the diff, automated checks and review conversation. Opening a pull request does not guarantee merge.

# Review, reviewer and approver

A review gives structured feedback on a pull request. Project roles differ. A reviewer may provide binding technical review in one project, while anyone may leave non-binding comments. An approver or maintainer may have authority to approve or merge.

# Continuous integration

Continuous integration, often called CI, automatically builds, tests, lints or scans proposed changes. A green check means the configured checks passed; it does not replace human design or security review.

# Maintainer

A maintainer carries ongoing responsibility for some or all of a project. This can include review, releases, governance, security, triage and community care. GitHub organization membership alone does not always mean maintainer.

# Good first issue and help wanted

These labels indicate work the project believes is approachable or welcomes help with. Labels can become stale, so read the discussion and confirm availability.

# CLA and DCO

A Contributor License Agreement grants specified contribution rights through an agreement. The Developer Certificate of Origin is a certification commonly recorded through commit sign-off. They are different mechanisms.

# Upstream and downstream

Upstream is the original source or dependency from which changes flow. Downstream is a consumer, distribution or fork receiving those changes. The meaning depends on context.
